작성 일시: `2026-05-15 21:17:33 KST`

이 문서는 MCP 게이트웨이 오픈소스 분석에서 도출한 최종 권고를 CoreMCP personal gateway 목적에 맞게 적용하기 위한 개발 범위를 고정한다.

## 개발 목적
- 외부 MCP gateway 사례에서 CoreMCP에 즉시 가치가 큰 보안/확장성 패턴을 선별한다.
- 가장 긴급한 STDIO command allowlist를 우선 구현해 command injection 계열 위험을 낮춘다.
- Plugin Framework, Client Profiles/Access Groups, OpenTelemetry, Inspector multi-session은 단계별 후속 개발 항목으로 문서화한다.

## 개발 범위
- Phase 1: `COREMCP_STDIO_ALLOWED_COMMANDS` 기반 STDIO command allowlist 구현.
- Phase 1: service create/update 및 runtime STDIO transport 모두에서 allowlist 적용.
- Phase 1: 거부 이벤트 audit log와 회귀 테스트 추가.
- Phase 1: 보안 문서/ADR/테스트 snapshot 업데이트.
- Phase 2 이후: Internal Plugin Framework, Client Profiles, OpenTelemetry, Inspector multi-session은 계획만 고정하고 이번 patch에서는 구현하지 않는다.

## 제외 범위
- SaaS/team/workspace/marketplace/billing 기능.
- 외부 LLM API dependency.
- 외부 Python plugin 동적 로딩.
- OPA/Rego/Cedar 같은 enterprise policy engine 도입.
- Smithery 등 외부 catalog에서 MCP 서버 자동 설치.
- container/macOS sandbox 적용.

## 공통 진행 규칙
- CoreMCP는 gateway이며 LLM service가 아니다. 외부 LLM API dependency를 추가하지 않는다.
- `AUTH_MODE=static_bearer` default와 token boundary invariant를 유지한다.
- STDIO 보안 강화는 admin UX를 크게 해치지 않도록 환경변수로 allowlist를 확장 가능하게 한다.
- 거부 응답/audit에는 전체 command path, args, env, token을 기록하지 않는다.
