이 문서는 신규 문서 `coremcp-design-patterns-to-absorb.md`를 **현재 프로젝트 목적**에 맞게 다시 해석하고, 구현 범위가 SaaS/Marketplace 방향으로 과확장되지 않도록 고정하기 위한 작업 문서다.

## 개발 목적

현재 CoreMCP 프로젝트의 목적은 **개인용 CoreMCP Gateway + 도구함 관리 시스템**을 안정적으로 완성하는 것이다.

핵심 사용 시나리오는 다음이다.

- Mac mini 또는 개인 서버에서 CoreMCP를 24/7 실행한다.
- Claude Code, Claude, ChatGPT, Cursor, OpenClaw 등 외부 AI client에는 CoreMCP 하나만 연결한다.
- CoreMCP는 개인 도구함에 담긴 MCP tool만 노출한다.
- downstream MCP credential은 CoreMCP vault에만 저장하고 외부 client에는 절대 노출하지 않는다.
- `/mcp`는 항상 인증, token boundary, SSRF guard, policy, audit log를 거친다.
- launchd, backup, logrotate, route smoke, ops smoke로 개인 운영 안정성을 보장한다.

따라서 신규 MD의 SaaS 패턴은 “바로 SaaS를 만드는 계획”이 아니라, **현재 개인용 Gateway를 더 안전하고 운영 가능한 구조로 만드는 데 필요한 패턴만 선별 흡수**한다.

## 개발 범위

- 신규 MD의 패턴을 현재 personal gateway 목적 기준으로 재분류한다.
- 이미 구현된 P0/P1/P2/P3 기능을 깨지 않고 보강한다.
- 개인 도구함 운영에 직접 도움이 되는 항목만 구현 계획에 포함한다.
- tool-level on/off, dangerous tool 제한, schema drift 표시, request-id/metrics, Admin UX polish처럼 현재 사용자 가치가 명확한 항목을 우선한다.
- 실제 reboot/Tailscale/OAuth client compatibility처럼 코드가 아닌 외부환경 검증 항목은 별도 Phase로 분리한다.

## 제외 범위

- 팀/조직 멀티테넌시 실제 구현.
- public marketplace, publisher profile, verified badge, review queue 공개 운영.
- billing, quota, abuse automation.
- 외부 plugin package loading/sandbox runtime.
- REST/gRPC/Database-to-MCP adapter 실제 구현.
- PostgreSQL/Redis 전환 강제.
- Kubernetes/Enterprise Private Cloud 배포.
- 외부 LLM API 의존성 추가.

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.

- 문서에 없는 범위 확장은 하지 않는다.
- `AUTH_MODE=static_bearer`는 기본값으로 유지한다.
- OAuth/CIMD/DCR은 optional mode로 유지한다.

- `Mcp-Session-Id`는 인증 수단으로 취급하지 않는다.
- downstream credential은 vault abstraction으로만 접근한다.
- raw tool arguments/result는 저장하지 않는다.
- tool icon은 `<img src>`만 사용하고 inline SVG는 금지한다.

## 현재 프로젝트 목적 기준 재분류

### 흡수 기준

| 기준 | 설명 |
|---|---|
| 개인 운영 안전성 | token boundary, SSRF, credential vault, audit, backup/reboot/Tailscale에 도움이 되는가 |
| 도구함 품질 | 개인이 도구를 쉽게 등록/검증/선택/비활성화할 수 있는가 |
| 외부 client 연결성 | Claude Code/ChatGPT/Cursor/OpenClaw 연결이 쉬워지는가 |
| 장애 격리 | downstream 하나의 장애가 전체 gateway 장애가 되지 않게 하는가 |
| 관측 가능성 | 문제 발생 시 request/tool/service 단위로 추적 가능한가 |
| 범위 절제 | SaaS team/marketplace/billing 구현으로 번지지 않는가 |
