작성 일시: `2026-05-11 22:18:42 KST`

이 문서는 `coremcp-docs/` 문서팩을 정본으로 삼아 CoreMCP 개인용 MCP Gateway를 처음 구현하기 위한 범위를 고정하고, 구현이 목적 밖으로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

CoreMCP를 **본인 1명이 Mac mini에서 운영하는 개인용 MCP Toolbox + Authenticated MCP Gateway**로 구현한다.

최초 목표는 `Claude Code → CoreMCP /mcp → fake downstream MCP → tool result` 흐름을 성공시키는 P0 vertical slice이며, 이후 문서에 정의된 P1/P2/P3 순서대로 실제 MCP 연결, dual token, credential vault, Web Admin UI, launchd 운영 안정화까지 확장한다.

## 개발 범위

- 문서 정합성 고정 및 구현 전제 정리
- Python/FastAPI backend scaffold (`apps/api`)
- 테스트용 downstream MCP server (`apps/fake-mcp`)
- Next.js Web Admin UI scaffold (`apps/web`)
- MCP Streamable HTTP `/mcp` endpoint: `initialize`, `tools/list`, `tools/call`, `ping`, session, SSE 최소 구현
- MCP protocol version negotiation: `2025-11-25`, `2025-06-18`, 누락 fallback
- Dual token model: `cmcp_admin_*` 파일 기반, `cmcp_client_*` DB hash 기반
- SQLite + Alembic schema: users, services, tools, aliases, toolbox, tokens, logs, jobs
- Downstream proxy: no token passthrough, timeout, error mapping, idempotency/cancellation 후속
- Credential vault: macOS Keychain 기본, Fernet fallback
- SSRF guard, metadata scanner, SVG/icon XSS 방어 정책 구현
- Web Admin UI: token 입력, dashboard, service registry, toolbox, clients, logs, settings/tokens, playground
- Operations: launchd, backup, log rotation, Tailscale 옵션, runbook smoke test
- Optional P3+: OAuth 2.1, CIMD first, DCR fallback, JWKS/JWT, Resource Indicator

## 제외 범위

- SaaS multi-tenant, workspace invitation, RLS, billing, public marketplace, SOC2/GDPR 자동화
- 외부 LLM API 호출 기능 또는 CoreMCP 내부 LLM orchestration 기능
- P0~P3 안정화 전 PostgreSQL/Redis/Arq를 기본 경로로 전환
- stdio MCP hosting. 문서상 RCE 위험 때문에 제외
- resources/prompts/sampling/elicitation/tasks 구현. 요청 시 `-32601` 반환만 수행
- 공개 배포용 legal docs, pricing, onboarding growth flow
- 문서에 없는 신규 기능 또는 무관한 리팩토링

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- 구현 중 발생한 이슈는 해당 Phase의 `이슈 및 수정`에 기록하고, 해당 Phase 안에서 해결한다.
- 체크박스 상태를 실제 진행 상태와 맞게 업데이트한다.
- 문서에 없는 범위 확장은 하지 않는다.
- CoreMCP token은 downstream MCP로 절대 전달하지 않는다.
- MCP session id는 인증 수단으로 사용하지 않고, 모든 `/mcp` request에서 bearer를 재검증한다.
- `static_bearer`가 기본이며 OAuth/CIMD/DCR은 Optional Phase 전까지 latent 상태로 둔다.
- SQLite + single process + in-memory cache를 기본으로 구현하고, Redis/PostgreSQL/Arq는 adapter 경계만 남긴다.
- raw tool arguments/output은 기본 저장하지 않는다. debug trace는 opt-in + TTL 24h로만 허용한다.
- SVG icon은 기본 차단(`ICON_SVG_ENABLED=false`) 또는 sanitize 후 `<img>` 렌더링만 허용한다.

## 문서 기반 분석 요약

- 보안 문서가 구현에 직접적인 제약을 준다: no token passthrough, SSRF allowlist, Origin 처리, credential redaction, icon/SVG 방어.

- Keychain은 Mac mini 로그인/잠금 상태에 따라 실패할 수 있다. 장기 무인 운영이면 Fernet mode를 우선 검증한다.
