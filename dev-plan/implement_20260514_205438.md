# implement_20260514_205438.md

작성 일시: `2026-05-14 20:54:38 KST`

이 문서는 이번 개발의 범위를 고정하고, 구현이 목적 밖으로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

직전 Web UI 검증 세션(Playwright 자동화)에서 발견한 두 가지 실제 결함의 임시 fix를 정식 fix로 대체하고, 동일한 회귀를 미래에 1분 내 자동 감지할 수 있게 한다.

발견된 결함:

1. CORS middleware 누락 — `apps/api/coremcp/main.py` 에 `CORSMiddleware` 가 등록되어 있지 않아, `infra/scripts/run-local.sh` 의 의도된 분리 origin 구성(web `:3003` ↔ api `:8787`)에서 모든 인증 GET 이 preflight 405 로 차단됨. Web Admin Dashboard 에 "CoreMCP API에 연결할 수 없습니다" 배너만 보이고 데이터는 단 한번도 받아본 적 없는 상태였음.
2. DB bootstrap 순서 버그 — `SCHEMA_SQL` 의 `CREATE INDEX idx_mcp_services_transport ON mcp_services(transport_type, status)` 가 `_ensure_legacy_columns` 보다 먼저 실행되어, `transport_type` 컬럼이 없는 기존 P0 DB는 부팅이 `sqlite3.OperationalError: no such column: transport_type` 로 실패. `code-level audit` Critical #3 "SCHEMA_SQL + 부분 마이그레이션의 일관성 부재" 의 실제 재현.

두 결함 모두 직전 세션에서 임시 fix(`main.py` 에 origin 하드코딩 CORSMiddleware / `bootstrap()` try–retry)는 적용되어 있다. 이 dev-plan 은 임시 fix 를 정식 fix 로 대체하고, 재발 방지 자동 검증을 추가한다.

## 개발 범위

- Phase 1: 임시 CORS fix 를 환경변수 기반 정식 fix 로 대체.
- Phase 2: bootstrap 의 raw `SCHEMA_SQL` + `_ensure_legacy_columns` 를 Alembic 단일 소스화로 근본 대체.
- Phase 3: Playwright UI smoke 자동화 — 직전 세션의 `/tmp/coremcp_ui_test/run.py` 를 프로젝트로 정식 편입하고 `make ui-smoke` 로 묶음.

## Phase 2. Alembic 단일 소스화 (DB drift 근본 해결)

## 잔여 리스크 / 후속 과제

- Alembic 단일 소스화 이후에도 `INSERT OR IGNORE INTO users / toolboxes` data seed 는 `bootstrap()` 에 남는다. 향후 multi-user 가 도입되면 이 seed 도 마이그레이션 또는 별도 seed 명령으로 옮길지 재검토.

- 코드 리뷰 Critical 의 나머지(`#1` init proxy 30 s 블로킹, `#2` OAuth 영속화, `#11`·`#12` 모듈 분해, `#14` inflight TTL) 은 각각 별도 dev-plan 에서 진행.
- CORS allow_origins 와 admin UI 인증의 결합 모델(예: same-origin 강제 옵션) 은 별도 보안 ADR 로 검토. 본 dev-plan 은 단순 환경변수화에 한정.
