이 문서는 CoreMCP Web Admin의 **메뉴 구조와 전체 레이아웃을 Multica dashboard 형식에 맞게 재구성**하기 위한 개발 범위를 고정하고, 구현이 목적 밖으로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

현재 CoreMCP Web Admin은 Multica 색/토큰 일부를 흡수했지만, 레이아웃 자체는 여전히 “상단 hero + horizontal nav + 모든 섹션 동시 렌더링” 구조다. Multica의 실제 제품 레이아웃은 **좌측 app sidebar + 상단 48px page header + route별 단일 content pane** 구조이므로, CoreMCP도 같은 정보 구조로 재구성한다.

목표는 CoreMCP를 SaaS처럼 확장하는 것이 아니라, 개인용 MCP gateway 목적에 맞게 다음을 달성하는 것이다.

- 좌측 고정 sidebar 중심의 운영 콘솔로 재구성.
- route별로 필요한 화면만 렌더링.
- 메뉴를 CoreMCP 운영 흐름 기준으로 재정렬.
- admin token/health 상태를 앱 chrome에 통합.
- 기존 보안 invariant와 Codex CLI exec first flow 유지.

## 개발 범위

- Multica layout pattern을 CoreMCP에 맞게 흡수한다.
- 기존 `AdminShell`의 상단 hero/horizontal nav를 sidebar app shell로 대체한다.
- `PageHeader` primitive를 추가하고 모든 route에 48px header를 적용한다.
- 메뉴를 sidebar group 구조로 재구성한다.
- 현재 `AdminConsole`의 “모든 섹션 한 화면” 구조를 route별 화면 구조로 분리한다.
- admin token 입력/상태/health를 sidebar 또는 compact auth panel로 이동한다.
- docs/design과 coremcp-docs frontend UX 문서를 실제 레이아웃 기준으로 갱신한다.

## 제외 범위

- Multica의 workspace/team/invitation/pinned/dnd/marketplace/billing 기능 도입 금지.
- 외부 LLM API dependency 추가 금지.
- 새 UI library 도입 금지. 필요한 sidebar/header primitive는 CoreMCP 내부 Tailwind/React로 구현한다.
- OAuth/CIMD 기능 변경 금지.
- backend API 동작 변경 금지. 레이아웃 재구성은 Web Admin 중심이다.

## Multica 레이아웃 실측 요약

Multica의 실제 dashboard 형식은 다음 구조다.

```tsx
<SidebarProvider className="h-svh">
  <AppSidebar />
  <SidebarInset className="relative overflow-hidden">
    <PageHeader className="justify-between px-5">...</PageHeader>
    <div className="flex flex-1 min-h-0 flex-col ...">...</div>
  </SidebarInset>
</SidebarProvider>
```

핵심 특징:

- `SidebarProvider`: 전체 app frame을 `h-svh`, `flex`, `min-h-0` 기준으로 고정.
- `AppSidebar`: 좌측 `variant="inset"` sidebar, 기본 폭 256px, 모바일은 offcanvas.
- Sidebar header: 제품/작업 공간 identity + quick action.
- Sidebar content: group label + menu item + active state.
- Sidebar footer: 도움말/보조 action.
- `PageHeader`: 모든 주요 route 상단에 `h-12 border-b px-4/px-5`.
- Content: route마다 하나의 primary pane. list page는 toolbar + list/table, detail page는 header + tabs/content.
- Typography: `text-sm`, `text-xs`, `font-medium` 중심.
- Active state: `bg-sidebar-accent`, `text-sidebar-accent-foreground`, hover는 active를 덮지 않음.

## CoreMCP에 맞춘 메뉴 재구성

Multica의 workspace 개념은 가져오지 않고, CoreMCP의 개인 gateway 흐름으로 group을 바꾼다.

```text
CoreMCP Sidebar
├── Header
│   ├── CoreMCP
│   ├── Local Gateway / API base
│   └── Auth status badge
├── Quick Action
│   └── MCP 추가/등록
├── Gateway
│   ├── Dashboard
│   └── Logs
├── MCP
│   ├── Services
│   ├── 도구함
│   └── Playground
├── Connections
│   ├── 연결된 AI client
│   └── Codex CLI exec guide
└── Configure
    ├── Settings/Tokens
    └── Health / About
```

초기 구현에서 신규 route를 과도하게 늘리지 않기 위해 다음처럼 매핑한다.

| Sidebar label | Route | 현재 구현 재사용 |
|---|---|---|
| Dashboard | `/` | `DashboardSection` |
| Services | `/services` | `ServicesSection` |
| 도구함 | `/toolbox` | `ToolboxSection` |
| Playground | `/playground` | `PlaygroundSection` |
| 연결된 AI client | `/clients` | `ClientsSection` |
| Codex CLI exec guide | `/clients` 내부 guide panel 우선, 후속 `/clients/connect` |
| Logs | `/logs` | `LogsSection` |
| Settings/Tokens | `/settings` | `SettingsSection` |
| Service detail | `/services/[id]` | `ServiceDetailConsole` layout 재적용 |
