이 문서는 `coremcp-design-patterns-to-absorb.md`에서 개인용 CoreMCP 목적에 맞게 흡수 가치가 높은 항목만 선별하고, 구현이 SaaS/marketplace 범위로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

CoreMCP personal gateway의 운영 안정성, 도구 제어 UX, schema drift 가시성, downstream 방어선을 강화한다.

## 개발 범위

- Tool preset UX/API: `readonly`, `full_access`, `dangerous_off`
- Schema diff detail: validation summary에 added/removed/changed tool 상세를 보존하고 Web에서 요약 표시
- Downstream response sanitizer: JSON content-type + response size cap
- Scheduled refresh: local launchd로 모든 활성 service validation을 주기 실행하는 안전한 script/plist
- Private service metadata: category/homepage/documentation/logo 필드 API/UI 보강

## 제외 범위

- team/workspace 멀티테넌시
- public marketplace / publisher / billing / quota
- REST/gRPC-to-MCP adapter
- Redis 필수화
- 외부 plugin sandbox
- gateway middleware 대규모 리팩터

## 코드 레벨 구현 가능성 체크

| 항목 | 가능 여부 | 근거 | 구현 판단 |
|---|---:|---|---|
| Tool preset UX/API | 가능 | `toolbox_tool_overrides`, `upsert_tool_override` 존재 | 구현 |
| Schema diff viewer | 가능 | `validation_summary.schema_drift`와 service tools cache 존재 | 구현 |
| Response sanitizer | 가능 | `DownstreamMcpClient` 단일 outbound 경로 존재 | 구현 |
| Scheduled refresh | 가능 | `validate_service()` 재사용 가능, launchd 구조 존재 | 구현 |
| Service metadata | 가능 | DB schema에 `category/logo_url/homepage_url/documentation_url` 존재 | 구현 |
| Middleware chain 리팩터 | 가능하지만 위험 | `main.py` route가 넓어 대규모 diff 필요 | 이번 범위 제외 |
| Redis-backed cache | 가능하지만 불필요 | 개인용 단일 프로세스/SQLite로 충분 | 제외 |
