작성 일시: `2026-05-15 06:03:23 KST`

이 문서는 직전 범위에서 제외했던 MCP 명세/구조 항목을 실제 구현 가능한 단위로 쪼개고, personal gateway 안정성을 깨지 않는 순서로 진행하기 위한 작업 문서다.

## 개발 목적

CoreMCP의 MCP 명세 호환성을 한 단계 더 높인다. JSON-RPC batch, downstream notification fan-out, progress notification 전달을 구현하고, `main.py`/`repository.py` 대형 파일 분해는 회귀 위험을 낮추는 facade/모듈 추출 기반부터 시작한다.

## 개발 범위

- Phase 1: JSON-RPC batch request 지원.
- Phase 2: downstream `notifications/progress`와 `notifications/resources/updated`를 CoreMCP SSE bus로 fan-out.
- Phase 3: HTTP SSE downstream response와 STDIO notification line에서 notification callback 처리.
- Phase 4: 구조 분해 foundation — app factory/repository facade 모듈을 추가해 다음 라우터/도메인 분해의 import 경계를 만든다.
- Phase 5: 테스트/문서/dev-plan 동기화.

## 제외 범위

- Full-duplex streaming response body를 client `/mcp` POST와 직접 연결하는 것. CoreMCP는 fan-out SSE channel(`/mcp` GET)로 progress/resources updated를 전달한다.
- `resources/subscribe` capability 활성화. 현재 `subscribe:false` 유지.
- JSON-RPC batch의 병렬 실행. 순서 보존과 안전한 side-effect 처리를 위해 sequential 처리.
- `main.py`/`repository.py` 전체 route/domain split을 한 번에 완료하는 위험한 대규모 이동. 이번 phase는 안전한 경계 모듈 추가와 후속 분해 준비까지 한다.
- SaaS/team/workspace/marketplace/billing 기능.
- 외부 LLM API 의존성 추가.
