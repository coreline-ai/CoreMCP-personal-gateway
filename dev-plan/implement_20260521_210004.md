## 개발 목적

Project Docs MCP 가 `~/projects` 하위 README/Markdown 을 read-only 로 노출한 것과 동일한 패턴으로, **git 상태/이력/diff/blame** 을 read-only MCP 도구로 노출하는 `apps/git-workspace-mcp` 를 신설한다. 개인 CoreMCP 도구함에 등록되면 Codex/Claude 가 "지난 1주일 변경 활동", "uncommitted 작업", "README vs 실제 변경 drift" 같은 일상 질의에 직접 답할 수 있다.

## 개발 범위

- Phase 1: scaffold (`apps/git-workspace-mcp/{pyproject.toml, package, stdio entry, JSON-RPC dispatch}`)
- Phase 2: `git_runner` subprocess wrapper + security layer (root resolve / subcommand allowlist / argv 검증)
- Phase 3: 4 read-only tools — `repo_list`, `repo_status`, `repo_log`, `repo_branch_list`
- Phase 4: `repo_diff` (truncate + secret redact) + `repo_blame`
- Phase 5: `repo_recent_activity` 집계 + `infra/scripts/register-git-workspace-mcp.sh` + `make git-workspace-register` + `make test` 통합

## 제외 범위

- write / push / fetch / pull / commit / checkout / reset / merge / rebase 모든 mutating 명령
- `git` 외 외부 도구 (예: GitHub CLI, hub, etc.)
- 외부 LLM API 의존성
- SaaS multi-tenant / shared workspace
- monorepo 별 worktree 다중 결과 통합 — 첫 cycle 은 단일 path
- non-Markdown 코드 본문 검색 (Local Code Search 별도 MCP)

## Phase 2. git_runner + security

### 목표

`git -C <path> <subcommand> [args]` subprocess wrapper 와 보안 layer 를 먼저 만들고 회귀로 고정한다.

### 구현 태스크

- [x] `git_workspace_mcp/security.py`
  - `resolve_repo_root(path: str | None) -> Path` — `GIT_WORKSPACE_ROOT` env 또는 기본 `~/projects`
  - `resolve_repo_path(root: Path, name: str) -> Path` — symlink resolve 후 root 하위 검증, 비-git 폴더 거부
  - `normalize_ref(ref: str) -> str` — `refs/heads/`, `refs/remotes/origin/`, `HEAD~n`, `<sha>`, `<branch>` 만 허용. shell metachar 거부
  - `redact_secrets(text: str) -> str` — sk-/ghp_/xoxb-/JWT/`password=`/`BEGIN PRIVATE KEY` 마스킹. `GIT_WORKSPACE_REDACT_SECRETS=false` 시 bypass
- [x] `git_workspace_mcp/git_runner.py`
  - `ALLOWED_SUBCOMMANDS = {"status", "log", "diff", "branch", "blame", "show", "rev-parse", "rev-list", "for-each-ref"}` — 화이트리스트
  - `async def run_git(repo: Path, subcommand: str, *args: str, max_output_bytes: int = 1_000_000, timeout_seconds: float = 10.0) -> str`
  - subcommand allowlist 검증 + argv string 검증 (`--` separator 또는 shell metachar 거부)
  - subprocess `asyncio.create_subprocess_exec("git", "-C", str(repo), subcommand, *args, ...)`, stdout 캡쳐, exit non-zero 시 raise
  - stdout `> max_output_bytes` 시 truncate
- [x] `tests/test_security.py`
  - root 외부 path 거부 (`/etc/passwd`)
  - symlink escape 거부 (root 안의 symlink 가 root 밖을 가리킴)
  - 비-git 디렉토리 거부
  - disallowed subcommand 거부 (`push`, `commit`, `checkout`, `pull`, `fetch`, `reset`)
  - shell metachar argv 거부 (`;`, `&&`, `|`, ` ` 등)
  - secret redact: `sk-abcdef123` → `sk-***`
- [x] `tests/test_git_runner.py`
  - 미니 git repo fixture (tmp_path 안 `git init` + 1 commit) 만들고 `status` / `log` 실제 호출 성공

## 잔여 리스크 / 후속 과제

- `git blame` 이 binary file 또는 huge file 에서 hang 가능 — timeout=10s 로 차단
- monorepo 의 `repo_log` 가 numstat 까지 포함하면 응답 큼 — limit 기본 20 충분히 작음
- `GIT_WORKSPACE_ROOT` 외 root 등록 (예: 회사 폴더 별도 root) 은 추후 multi-root 지원 backlog
- diff/blame 외 코드 본문 search 는 별도 MCP (Local Code Search) 로 분리
- shallow clone repo 에서 일부 log 응답 누락 가능 — 응답 metadata 에 `shallow: true` 표기 backlog
